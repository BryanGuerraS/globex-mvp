ESTADO DE LA CAPTURA
Lee casos[i].captura antes de puntuar. estado=RECIBIDA confirma recepción de HTTP 200 con un objeto JSON; no certifica ejecución ni calidad. ejecutado y error_ejecucion, si aparecen, son copias del endpoint. ejecutado=false o ejecución no confirmada no equivalen automáticamente a una respuesta vacía.
SIN_CAPTURA, SIN_CONFIRMACION y ERROR_HTTP_O_FORMATO son incidencias de evidencia/transporte. Para esos casos no se exige una rúbrica innecesaria: registra el pendiente con su ID, sin asignar cero ni inferir éxito.
Una RECIBIDA con ejecución confirmada permite observar campos omitidos por el propio endpoint; aplica la regla del KPI correspondiente. Revisa captura.incidencias_estructura y captura.incidencias_identificacion si existen. error_ejecucion no decide por sí solo: un turno posterior a una pausa puede no requerir respuesta.
pregunta_devuelta_distinta o mensajes_devueltos_distintos conservan discrepancias con la solicitud validada; comprueba si impiden vincular la evidencia. Nunca sustituyas la pregunta de referencia para favorecer el resultado.
Ausente, null, "", [], false y 0 son estados diferentes. No conviertas desconocidos en ceros, booleanos en importes ni una propiedad ausente en un valor confirmado.

RUTAS DE RESPUESTA DEL CASO
En las rutas siguientes, caso significa un elemento de casos[].
- caso.respuesta: salida textual íntegra; puede ser cadena vacía o null si así se recibió.
- caso.mensajes_bot: componentes del mismo resultado, normalmente objetos con tipo, texto y opciones. Lee sus textos y botones en orden cuando la estructura lo permita.
- caso.otras_salidas[]: cada elemento indica origen y contenido, que puede ser texto o una estructura recibida. No lo confundas con otra pregunta ni cuentes varias veces el caso.
Lee todas las representaciones disponibles. La mera presencia de otra representación no demuestra un error; conserva sus diferencias y aplica el método. No deduzcas contenido de imágenes, archivos o enlaces que no se entregue como evidencia.

Evalúa exclusivamente Orientación. Las fichas vigentes de DERIVACION tienen REQUIERE DERIVACIÓN: SÍ y respuesta orientativa; no exijas su literalidad.
Observada=SÍ cuando comunica claramente que la solicitud actual será atendida por un asesor/persona de Globex, o propone una conexión directa y pertinente. Observada=NO cuando no orienta, intenta resolver automáticamente lo que requería persona o solo hace una mención genérica.
Un menú, una mención histórica o una invitación opcional genérica no acreditan por sí solos la orientación necesaria. No exijas nombre, teléfono, pausa, resumen, consola ni recepción humana. Este indicador no certifica una transferencia ejecutada.
Cumple=true si esperada=SÍ y observada=SÍ; false si observada=NO. Ausencia real de respuesta en ejecución confirmada: NO y false. Captura ausente/incierta: observada=null y cumple=null.
KPI=100*casos_que_cumplen/casos_con_orientacion_decidida. Meta>=90 %. El banco solo tiene positivos: no calcules derivaciones innecesarias, precisión global ni contrapeso de falsos positivos.

INVENTARIO, VERSIONES Y COBERTURA
ids_previstos es el universo completo del banco; ids_seleccionados identifica lo solicitado en esta corrida. Una selección parcial no constituye una ejecución completa. No generes notas para ID no recibidos ni conviertas una falta de captura en un cero.
Numerador: éxitos definidos por este KPI. Denominador: casos con veredicto decidido, incluidos fallos confirmados. Veredictos no determinables son null y se conservan como pendientes. Si el denominador es cero, porcentaje=null.
Cobertura=100*casos_decididos/len(ids_previstos). Si hay ID faltantes o pendientes, el agregado es PARCIAL y cumplimiento de meta=null, salvo el control de seguridad de PRODUCTOS con incumplimiento ya demostrado. Sin inventario válido tampoco declares cumplimiento final.
Con banco completo resuelto, compara contra la meta sin redondear previamente. Muestra porcentajes con dos decimales. Para el total suma conteos; no promedies porcentajes de universos de tamaños distintos. Las repeticiones y versiones se evalúan por separado; no escojas el mejor duplicado ni extrapoles el banco a todos los leads.
